## 1. Статуси задач Backlog → Todo → In Progress → Done

* **Backlog** — Сховище всіх запланованих послідовних тренувальних завдань, практичних модулів Git, TypeScript, React, Laravel 
* та Inertia. Задачі не мають чітких дедлайнів.
* **Todo** — Усі навчальні модулі спочатку мають статус Todo, є найближчим пріорітетом у робочому циклу завдань. 
* Вони повністю описані, оцінені та готові до взяття в роботу.
* **In Progress** — Після початку роботи над модулем тікет переводиться в In Progress. Це задачі, над якими прямо зараз працює 
* розробник. Під час перевірки PR тікет залишається в In Progress.
* Одночасно у розробника в цьому статусі має бути не більше 1–2 задач.
* **Done** — Завдання переходить у цей статус, після повного завершення і лише після підтвердження ментора. 
* Це означає, що код протестований та злитий у головну гілку (main).

## 2. Статуси branch → commits → PR → review → merge

* **Branch** - Кожне завдання виконується в окремій гілці та передається через Pull Request. Розробку наступного модуля 
* можна починати, навіть якщо Pull Request попереднього ще не змерджено. У такому разі гілка наступного модуля створюється 
* від гілки попереднього, а новий Pull Request спрямовується в гілку попереднього модуля.

* **Commits**
* Робити невеликі, логічно завершені коміти з поміткою docs - якщо в PR додано структуру і першу документацію процесу адаптації,
* або chore - більш узагальнений технічний варіант. Використовувати зрозумілі повідомлення в теперішньому часі.

* **PR**
* Створюйте PR, коли код готовий до інтеграції.

* **Review**
* Перед мержем необхідно отримати підтвердження ментора. Якщо є зауваження, то вони виправляються в тій самій гілці та PR.

* **Merge**
* Після успішного рев'ю та проходження всіх перевірок гілка зливається в цільову main.

## 3. Шаблон щоденного звіту

* Звіт за dd.mm.yyyy

* Вивчив:
* структуру навчального репозиторію
* правила щоденних звітів і review
* Зробив:
* створив репозиторій і базову структуру
* додав workflow та PR template
* Практичний результат:
* PR: https://github.com/example/onboarding/pull/7
* Що було незрозуміло або складно:
* було незрозуміло, які файли мають залишатися лише локальними.

## 4. Шаблон блокера

Якщо роботу над завданням неможливо продовжувати через технічні проблеми або інші перешкоди, додається лейбл blocked
до завдання та залишається детальний коментар за наведеним нижче шаблоном.

**Очікуваний результат:**

**Уже виконані перевірки:**
