# Local Git Workflow

## Working tree

Ваша локальна папка з файлами на комп'ютері, де ви безпосередньо пишете код. Зміни тут є незафіксованими.
Git бачить, що файли змінилися або з'явилися нові файли, але вони ще не готові до збереження в історію.
Використовуйте git status, щоб переглянути поточний стан робочого дерева.

## Staging area

Проміжний буфер перед створенням коміту. Додайте файл за допомогою команди "git add <file>" або додайте всі заплановані зміни командою "git add .".
Перед виконанням коміту перегляньте підготовлені зміни за допомогою команди "git diff --staged".

## Repository

Місце збереження всіх зафіксованих комітів та історії змін.

## Основні команди

### Робота зі змінами
* `git status` — Перевірити стан робочої директорії та індексу (які файли змінено, які готові до коміту).
* `git add <file>` — Додати конкретний файл до Staging Area.
* `git add .` — Додати **всі** змінені та нові файли до Staging Area.
* `git commit -m "Повідомлення"` — Зафіксувати зміни з індексу в Repository, створивши новий коміт.
* `git log` — Переглянути історію комітів.

### Робота з гілками та синхронізація
* `git branch` — Показати список локальних гілок.
* `git checkout -b <branch-name>` — Створити нову гілку та перейти на неї.
* `git switch <branch-name>` — Перейти на існуючу гілку.
* `git push origin <branch-name>` — Відправити локальні коміти у віддалений репозиторій.
* `git pull` — Завантажити останні зміни з віддаленого репозиторію та об'єднати їх із локальними

## Безпечне скасування локальних змін

- Видалити неіндексовані (unstaged) зміни в конкретному файлі:

  ```git restore <шлях_до_файлу>```

- Прибрати файл з індексу (unstage), зберігши локальні редагування:

  ```git restore --staged <шлях_до_файлу>```

- Скасувати всі неіндексовані зміни у відстежуваних файлах поточного каталогу:

  ```git restore .```

Ніколи не використовуйте команду git reset --hard без попередньої перевірки.
Вона одночасно видаляє як індексовані, так і неіндексовані зміни у відстежуваних файлах, що майже гарантує втрату незакоміченої роботи.

## Порівняння git diff з git diff --staged

git diff відображає тільки ті зміни, які знаходяться в Working tree, але не додані в Staging area.
Після виконання git add, ця команда більше не бачить змін.

git diff --staged відображає різницю між Staging Area та останнім комітом в репозиторії.
Використовується для перевірки того, що саме зараз відправиться в коміт.
